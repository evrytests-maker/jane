## Что делает расширение (по коду)

Расширение ведёт ролевой «трекер питания и здоровья» для персоны пользователя и бота: считает калории, сытость, воду, энергию, вес, болезни, эффекты и беременность. Оно просит основную модель дописывать в конец ответа скрытый тег `<!-- NN … -->`, разбирает его (`parser.js`), пересчитывает состояние (`nutrition-engine.js`, `conditions.js`, `effects.js`, `analyzer.js`) и рисует инфоблок под сообщением. Состояние хранится в `chat_metadata` (то есть в файле чата) и в `msg.extra`, а настройки — в `localStorage`. Опционально (режим «Отдельным запросом», «Восстанавливать тег» и кнопка «Пересчитать по карточкам») оно отправляет запрос в LLM через штатные `ConnectionManagerRequestService` / `generateRaw` ST. README и manifest описывают именно это, расхождений нет.

## Находки

Вредоносных находок нет. Замечания по приватности и качеству:

1. **Низкая (приватность, по дизайну). Контекст чата уходит в LLM, выбранную в профиле Connection Manager.**
   `index.js:1533-1575` (режим «Отдельным запросом»), `index.js:1439-1453` (fallback), `index.js:2920-2941` (кнопка «Пересчитать»):
   ```js

       persona ? `[Persona — ${userName}]\n${persona}` : '',
       ctxMsgs.length ? `[CONTEXT — already counted]\n${ctxMsgs.join('\n\n')}` : '',

   ```
   Уходят: до ~6 новых сообщений (по 6000 символов), 4 предыдущих (по 600), Description/Personality/Scenario карточки (по 3000 символов) и описание персоны (2000), а также записи лорбука, сработавшие на новые сообщения (`index.js:1584-1591`, `getWorldInfoPrompt`). Если пользователь выбрал в аналитике профиль с другим провайдером, чем основной, этот текст пойдёт и туда. Это заявленное поведение, о профиле сказано в UI (`index.js:2767-2771`), он выбирается явно. По умолчанию режим «В ответе модели» и «Восстанавливать тег» **выключены** (`fallbackOn()` по умолчанию `'false'`, `sideMode()` по умолчанию `'reply'`), то есть дополнительных запросов нет. 2. **Низкая (поведение). Подмена текста сообщений.** `index.js:1013-1018`, `index.js:1020-1028`:
   ```js
   msg.mes = cleaned; text = cleaned;
   if (Array.isArray(msg.swipes) && msg.swipe_id != null) msg.swipes[msg.swipe_id] = cleaned;
   try { stModule?.updateMessageBlock?.(N, msg); } catch (e) { /* пусто */ }
   ```
   Расширение вырезает из ответов бота «неправильные» формы своего служебного тега (```-блоки, строки «NN: …», незакрытые `<!-- NN`). Это правка пользовательских данных чата, но только удаление собственного тега. Регэкспы узкие (`/<!--\s*NN\b…/`, `/^\s*\[?\s*NN\b[\s:]+[^\n]*$/gim`), хотя последний может задеть строку, которая сама начинается с «NN:» в обычном тексте. В режиме «side» это включено всегда.

3. **Низкая (инъекция в промпт, по дизайну).** Расширение через `setExtensionPrompt` (`index.js:2104-2107`) и событие `CHAT_COMPLETION_PROMPT_READY` (`index.js:2160-2171`) добавляет в каждый запрос к основной модели блоки состояния и правила. Заодно `stripOldTagsFromMessages`/`onAfterCombinePrompts` вырезают старые теги из уходящего промпта (`index.js:2141-2158`) — только из промпта, сам чат не меняется. Это полностью соответствует описанию («уходит в промпт»).

4. **Информационно (XSS-гигиена, исправно).** Весь вывод в HTML делается через `innerHTML` (`index.js:2306`, `3300`, `3348`, `notifications.js:47`), но подставляемые строки проходят `esc()`/`escapeHtml()` (`index.js:82-84`, `notifications.js:18-20`). Это относится и к тому, что приходит от LLM: названия болезней/эффектов, самочувствие, еда, дата, `title=`-атрибуты. Числовые поля, приходящие из тега, приведены к числам (`parser.js:446-450`: возраст проверяется `parseInt` и диапазоном 14–110; пол, телосложение и образ жизни проверяются по белому списку). Незащищённых подстановок недоверенных строк не найдено. `notifications.js:47` подставляет только `NN_NOTIFY_ICONS[type]` (фиксированный словарь) и экранированный текст.

5. **Информационно (манифест).** `manifest.json`: `"homePage": ""` (пусто), `"auto_update": false`, `loading_order: 15`. Автообновление выключено, что снижает риск подмены кода через обновление. Ссылка на репозиторий есть только в `README.md`.

6. **Информационно (стиль/качество).** В консоль пишется много отладочных логов `[NN] …`, включая сам тег и итоги дней (`index.js:480`, `1351`, `1761`).
