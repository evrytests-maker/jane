# Аудит: claude-web (https://github.com/niemandswasser/claude-web)

**Вердикт:** 🟢 Чисто (с двумя информационными замечаниями — см. «Находки»)

## Что делает расширение (по коду)
Косметическая тема/«скин» для SillyTavern в стиле Claude Web: подключает CSS (`styles/{day,night}-{pc,mobile}.css`), перестраивает боковую панель, добавляет анимированного «Clawd», приветствие, список недавних чатов, переключатель персонажей, кнопки удаления сообщений/чатов. Настройки хранятся в `localStorage` (`claude-web:*`). В форке (последний коммит) добавлена только локализация интерфейса RU/EN/ZH. Внешнего кода и серверной части нет.

## Как работают loader-ы и index.js (то, на что просили обратить внимание)
- `manifest.json`: `"js": "loader-2.0.34.js"`, `version 2.0.34`, `auto_update: true`, `homePage`: `https://github.com/claudenoshujin/claude-web` (оригинальный автор). Выбор loader-а — **статический**: manifest указывает на конкретный файл; `index.js` loader-ы не выбирает и не загружает.
- В репозитории 27 файлов `loader-2.0.8.js … loader-2.0.34.js` (по 94–282 байта). Каждый содержит ровно одну исполняемую строку `import './index.js?v=2.0.N';` (проверено скриптом-grep для всех 27: номер в импорте совпадает с номером файла) плюс комментарий. Это только cache-busting: новое имя loader-а заставляет браузер/ST заново загрузить `index.js`. **Ни одного URL, `fetch`, `eval`, `atob`, динамического `import()` в loader-ах нет.**
- Diff между версиями loader-ов (и по всей истории `git log -p -- 'loader-*.js'`): меняются только номер версии в `?v=` и текст комментария. Ни одного сетевого адреса не добавлялось и не удалялось ни в одном коммите. Коммит форка 61ee83f переписал 25 старых loader-ов только сменой переводов строк (CRLF), содержимое при `--ignore-cr-at-eol` идентично; добавил loader-2.0.33/34.
- `index.js` (403 КБ, 8000+ строк, НЕ минифицирован, читаемый код с комментариями; заголовок: сгенерирован `tools/build-extension.js` — этого скрипта в репозитории нет, но сам `index.js` читаем и бандлов/упаковки нет). Стили берутся по адресу, выведенному из `import.meta.url` (локальные файлы расширения): `index.js:~278-296`.

## Находки
1. **🟡 Информационно / низкая: «Переустановить» и homePage ведут на репозиторий оригинального автора, а не на форк.** `index.js:286` `const CLAUDE_EXTENSION_REPO = 'https://github.com/claudenoshujin/claude-web';` и `index.js:7603` `post('/api/extensions/install', { url: REPO_URL, ... })`; `manifest.json` `homePage` — тоже claudenoshujin. Кнопка «Переустановить» (по клику, после confirm) удалит папку форка и установит оригинал (без RU-перевода) — функционально несоответствие, не вредоносность. Стоит понимать: содержимое оригинала может отличаться от этого форка; сам код оригинала в этой истории (до 445a682) также чист. Если мейнтейнер форка захочет, нужно заменить URL на свой.
2. **🟡 Информационно: единственный коммит стороннего автора** `61ee83f nimandswasser <solinvictus1274+1@gmail.com> "Add files via upload"` (2026-08-03) — массовая заливка файлов. Я сравнил его с родительским коммитом `445a682` (последний коммит оригинального автора) с `--ignore-cr-at-eol`: изменились только `README.md` (перевод + строка о форке), `index.js` (+499/−313, проверено построчно — добавлены `claudeInterfaceLanguage/claudeText`, русские строки, выпадающий список языка; удалена `ccPrefersChinese`; нет новых сетевых вызовов/eval/внешних строк), `manifest.json` (loader 2.0.32→2.0.34, версия), и два новых loader-а. Иконки (SVG/PNG) и все 4 CSS отличаются **только** переводами строк (CRLF), содержимое тождественно. Подмен ссылок нет.
3. **🟡 Рискованное (но заявленное) поведение: перезапись настроек темы ST.** `index.js:~986-1007` (`persistFullTheme`): `Object.assign(settings, THEME_VALUES); settings.theme = THEME_NAME; ... context.saveSettingsDebounced()` — расширение сохраняет в `powerUserSettings` свою тему и `custom_css` (строки 60/102 — встроенные темы с CSS-переменными), предварительно сохраняя снимок прежних настроек в `localStorage['claude-integrated-theme-restore:v2']` и восстанавливая его при отключении (`restorePreviousTheme`, ~1040-1063). Это заявленная функция скина; секретов/API-ключей/прокси не трогает.
4. **Инъекция module-script в страницу ST** (`index.js:4640-4695`): создаётся `<script type="module">` с жёстко заданным текстом — `import * as main from <script.js ST>` (+ `group-chats.js`, `popup.js`) и запись ссылок в `window.__clawdHostModules`; запасной вариант через `Blob`/`createObjectURL`. Источники — только модули самого ST (URL из `hostModuleRoot()`), содержимое статично. Удалённого кода нет. Нужно для штатного удаления чатов; не вредоносно.
5. `innerHTML` (index.js:3117, 4006, 4062, 4277, 5073, 5337, 5462, 7304, 7544-7614): строки собираются из статичных шаблонов/локализованных строк и числовых кодов HTTP; `showCcToast` получает текст через `ccEscapeHtml`. Удалённый контент в innerHTML не попадает. Картинки `img.src` — локальные URL ST (`getThumbnailUrl`, `characters/…`, `thumbnail` из ответа собственного сервера ST).
6. Листенеры `keydown` (index.js:3482, 5396, 6861-6921, 7007): только для UI-логики (Enter → анимация, Escape → закрыть меню, отметка активности). Ввод не записывается и не отправляется.
7. Обращения к чатам/персонажам: `getContext().characters`, `name1`, `/api/chats/recent` — только для отрисовки списка в боковой панели; результат нигде не отправляется наружу. Секреты (`/api/secrets/*`, `oai_settings`, `api_key`, `password`) не упоминаются нигде в коде и в git-истории (`git log --all -S'secrets'` по index.js — 0 совпадений).
8. Текстов, обращённых к ИИ-ассистентам/промпт-инъекций, не найдено (grep «ignore previous», «safe to» и т.п. — пусто). Комментарии в коде на китайском/русском — описание разработки.
